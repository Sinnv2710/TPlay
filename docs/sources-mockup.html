What a source file looks like (example, dummy site). No code, only where to look. The repository index lists several of these.
// source definition
{
  "id": "example-movies",  "name": "Example Movies",
  "version": 3,  "site": "https://example-movies.test",
  "list": {
    "path": "/movies?keyword={keyword}&genre={genre}&year={year}&page={page}",
    "card": "div.card",
    "fields": { "title": "h3", "poster": "img@src",
                "year": "p span:first-child", "link": "a@href" },
    "next": "a[rel=next]"
  },
  "filters": [
    { "name": "Genre", "param": "genre", "options": ["Action", "Comedy"] },
    { "name": "Year",  "param": "year",  "options": ["2020-2029", "2025"] }
  ],
  "detail": {
    "release": "div.release",
    "fields": { "name": ".name", "size": ".size",
                "seeds": ".seeds", "magnet": "a[href^=magnet:]@href" }
  }
}
// repository index
{ "name": "My sources", "sources": [ { "id": "example-movies", "version": 3,
    "url": "https://raw.example.test/me/sources/example-movies.json" } ] }

Please review

  1. Where does Sources live? Under Settings (as drawn), or as a button inside the Discover source picker only?
  2. Bundled source. Keep the current site as the one built-in source (so it works on first launch), or ship with no source and make you add a repository first, like Foldchiyomi?
  3. Self test. A manual "Run a self test" button (drawn), or also a quiet automatic test once a day that turns the dot yellow?
  4. Repository address. Any address you paste (as drawn), or only addresses from one allow-list you set in Settings?
  5. Sites that need code. If a site cannot be described in JSON (logins, scripts), skip it, or later allow a Kotlin source built into the app?

Limits to keep in mind: a JSON source can only read ordinary web pages where the data is in the HTML, and it breaks whenever the site changes its layout. You or the repository owner fixes it by updating the file.
